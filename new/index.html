--- layout: default title: New entry description: Write a new reaction. permalink: /new/ sitemap: false noindex: true csp: true --- {% comment %} new/index.html — the one-page "post from my phone" screen. The flow, one step at a time on the same page: 1. "What are you reading?" Tap the book. Books marked "reading" are big buttons at the top, because that's almost always the answer. 2. Not there? "Something else" shows every other log, plus "Start a new one", which asks for title, author/studio and type. 3. Write: chapter (filled in with the last chapter you logged), the text, and Post. Done. It's saved straight into the repo. How "Post" saves without opening GitHub: the page talks to GitHub's API using a posting key (a GitHub "fine-grained token") that you paste in once. The key is kept only in this phone's browser. It is never in the repo or on the site. See assets/js/new-entry.js for the details and the trade-offs. Without a key, the page still works the old way: it opens GitHub's new-file screen with everything filled in, and you tap Commit. sitemap: false and noindex: true keep this page out of search engines. It's a tool, not a page to read. csp: true switches on a safety rule for the browser (written in head.html, called a Content-Security-Policy). On this page, scripts may only come from this site, and the page may only talk to GitHub's API. So even if something sneaky got onto the page, it couldn't send your key anywhere else. {% endcomment %} {% comment %} Everything the page needs to know about the logs, handed to the JavaScript as data. type="application/json" means the browser never runs it; the script just reads it. That matters because the safety rule above blocks scripts written inside the page. For each log we also include the last chapter and a short bit of the last entry, so the write step can say "Last time: Ch 17, 'Nesta is still…'" and fill in the chapter for you. {% endcomment %} {% comment %} The data is built first, then every "" would otherwise end this block early and break the page. Tripped me up: jsonify makes text safe for JSON, but not for JSON sitting inside an HTML page.
